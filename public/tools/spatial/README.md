# 360° 空间音频（工具箱）

大厅 → 工具箱 → **空间音频**。浮层铺满窗口：左侧是 3D 舞台，右侧是控制台。听者在原点，1–4 个立体音响可以放在任意方位、任意远近、任意高度上；把音响拖到哪儿，耳机里听到的声音就来自哪儿。

## 怎么用

1. 点「播放」（音源固定为主播放器当前播放的歌曲；第一次会先读取并解码，稍等一两秒）。
2. 按住舞台上的音响拖动：
   - **角度**决定左右 / 前后；
   - **半径**决定远近（0.9–3.4 m）；
   - 按住 **Shift** 拖动，角度吸附到 15°。
3. 选中音响后，舞台上会出现 X（红）/ Y（绿）/ Z（蓝）三根坐标轴：拖轴线或轴端圆点直接改对应坐标（见下面「坐标轴拖拽」）。
4. 每个音响在右侧列表里有：
   - **音量**：单个音响的音量；
   - **高度**：0–3.0 m，0 = 地面；最高不超过当前距离；
   - **X / Y / Z**：以米为单位的坐标，步进 0.05 m，可直接输入。
5. Tab 聚焦舞台上的音响：←/→ 调角度（Shift 15°），↑/↓ 调远近，PageUp / PageDown 调高度（Shift 0.5 m），Delete 删除。
6. 「+ 加音响」最多加到 4 个；新音响会自动放到空闲方位，至少保留 1 个。
7. 音源固定为主播放器当前歌曲：fetch 当前 `src` → `decodeAudioData`；如果主歌正在放，会先暂停，关闭工具后恢复。播放器里没有歌、链接失效、跨域或解码失败都会在音源面板下方如实报错，不会退回任何内置测试音。

> HRTF 只有戴耳机才容易听出前后。外放音箱只能分辨左右；左右声道本身不是 3D。

## 坐标轴拖拽

选中音响后，从箱体底部原点（`worldPos(sp)`）画出三根轴：**X 红、Y 绿、Z 蓝**，带箭头、轴端字母和可拖拽圆点。

- 轴的世界长度默认 **1.0 m**；投影后屏幕长度不足 **34px** 时按比例放大，拖拽数学使用同一个世界长度，视觉和手感一致。
- 命中优先于转视角：点轴线段 9px 内或轴端 12px 内进入轴拖拽，`setPointerCapture`，不会触发空白处旋转。
- 世界位移 = `dot(屏幕位移, 轴屏幕方向) / |轴屏幕方向|² × 轴世界长度`，然后走 `setFromXyz` 反算回极坐标真源（X/Z 限 ±3.4 m，Y 限 0–3.0 m）。
- 轴拖拽同样会同步 Panner、舞台标签和右侧列表的 XYZ / 高度 / 音量读数；鼠标和触摸都走 Pointer Events。
- 悬停轴时光标为 `grab`，拖拽中为 `grabbing`，离开恢复。

限制：轴几乎正对相机时投影退化成一个点，会直接不画（否则放大倍率会失控）；到达距离 / 高度边界后轴端会停住，这是 `setFromXyz` 的钳位，不是掉帧。

## 控制台抽屉

右侧三个 section（预设 / 音源 / 音响）都是可折叠抽屉，点标题行开合：

- 默认：**预设收起、音源展开**（正在播放卡片 + 播放键在首屏）、**音响展开**；
- 音响卡片头部常显（名称 + 方位摘要 + 删除），音量 / 高度 / XYZ 收进卡片内；默认只展开当前选中的那只，点卡片头选中并展开，再点收起；
- 抽屉状态只保存在内存里，关闭工具后不持久化；删除键、键盘操作、列表读数刷新都不受影响。

## 音源与「正在播放」卡片

音源不再可选，**固定为主播放器当前播放的歌曲**（没有内置测试循环，也没有测试音兜底）。

音源面板顶部是一张「正在播放」卡片：

- **封面**：优先用队列里当前歌曲的 `cover`，经 `API.img(cover, 160)` 走 `/api/img` 代理；本地音乐的 `data:` / `blob:` 封面直接显示。队列里没有封面时退回主播放器「正在播放」大图的当前 `src`，再没有就显示音符占位图；加载失败也会切回占位图，不会出现破图。
- **文本**：歌名 + 歌手，都做单行省略；下面一行是平台标签（网易云 / QQ 音乐 / 酷狗 / 汽水 / 波点 / 酷我 / 本地 / 未知，`undefined` 和 `netease` 都算网易云）。
- **状态**：工具正在播放 →「正在播放」（琥珀小圆点，动画只动 opacity / transform）；暂停但已载入 buffer →「已暂停」；有歌但还没载入 →「按播放载入」；没有歌 →「播放器里没有歌」。
- **进度条**：卡片底部一条 3px 细线，按 `currentOffset() / activeBuffer.duration` 更新，只用 `transform: scaleX(...)`，不触发布局。
- 音源 section 收起时，标题行仍显示 `《歌名》`，不会看不到在放什么。

主播放器换歌（`trackchange` / `source` 事件）时：如果工具正在播放，会立即停播、进度归零、清掉旧 buffer 与 `state.songSrc`，提示「歌曲已切换，按播放重新加载」，**不会自动开播**；如果没在播放，同样清掉旧 buffer / 进度，只更新卡片。解码过程中主播放器换了歌，刚解出的旧 buffer 也会被丢弃。工具播放时会暂停主播放器，关闭工具后恢复。

## 关键帧动画（v1）

预设区展开后点「**关键帧动画…**」打开独立面板。它是一条**独立时间轴**，v1 不跟音源播放进度同步。

1. **时长**：1–60 秒，默认 8 秒；缩短时长会移除超出范围的关键帧。
2. **时间轴**：点击 / 拖动标尺移动播放头；点圆点选中关键帧。
3. **记录当前布局**：把当前整套音响（angle / distance / elevation / vol）和总音量记在当前播放头时间；同一时间 0.05 秒内重复记录会覆盖。
4. **播放 / 暂停 + 循环**：至少 2 个关键帧才能播放；相邻关键帧之间线性插值，角度走最短路径（处理 0/360 环绕）。
5. **删除选中 / 清空**：删除选中的关键帧或全部清空。
6. 音响按数组下标对应；两帧音响数量不一致时只处理较小的那一批，多出来的保持不动。
7. 关键帧跟着自定义预设保存（`presetSnapshot` 里带 `kf` 深拷贝），内置预设没有 kf；套用预设会停播并把播放头归 0。
8. 改关键帧（记录 / 删除 / 清空 / 改时长 / 改循环）会把预设下拉打回「当前布局（未保存）」。

限制：v1 没有缓动曲线、每帧单独编辑、导入导出、音源时间同步；面板先做成可迭代的入口，后面再调。

## 预设

控制台顶部是预设区：下拉列出内置 + 自定义预设，下面三个动作：

- **保存当前**：把当前布局（每只音响的 angle / distance / elevation / vol + 总音量 + 关键帧 `kf`）存成命名预设；
- **删除**：只删自定义预设，内置预设不可删；
- **设为全局 / 取消全局**：把当前选中的预设标记为全局默认。

内置预设：

| 名称 | 布局 |
| --- | --- |
| 双声道 | 2 只，左 90° / 右 270°，2.2 m，地面 |
| 四角环绕 | 4 只，45° / 135° / 225° / 315°，2.6 m |
| 近场 | 2 只，左 90° / 右 270°，0.9 m，总音量更低 |
| 宽场 | 2 只，左 90° / 右 270°，3.4 m，总音量更高 |
| 影院 | 4 只：前两只 35° / 325° 抬高 25°，后两只 135° / 225° 抬高 5° |

内置预设和自定义预设都只改音响布局、总音量和关键帧；音源始终是主播放器当前歌曲，套用预设不会切音源。

### 存储

- 自定义预设：`localStorage['lizi.spatial.presets.v1']`，数组，最多 40 个；名字不能和内置预设重名。每条包含 `speakers / master / kf`（老数据没有 kf 时按空关键帧处理；旧数据里的 `source` 字段直接忽略，不会导致加载失败）。
- 全局默认：`localStorage['lizi.spatial.global.v1']`，`{ name, at }`。
- 每次 `open()` 会自动套用全局预设；没有全局、或全局预设已被删除时保留当前布局。
- 用户改动布局 / 音量 / 关键帧后，下拉回到「当前布局（未保存）」，避免把改过的布局误认成某个预设。

### 对外 API

```js
window.LIZI_SPATIAL.getPresets();
// → [{ name, builtin, global, speakers: [{ angle, distance, elevation, vol }], master }, …]

window.LIZI_SPATIAL.applyPreset('影院');       // 套用预设，返回 boolean
window.LIZI_SPATIAL.getGlobalPreset();         // → 全局预设名或 null
window.LIZI_SPATIAL.setGlobalPreset('影院');   // 设置 / 传 null 取消，返回 boolean
window.LIZI_SPATIAL.savePreset('我的布局');    // 保存当前布局，返回 boolean
window.LIZI_SPATIAL.deletePreset('我的布局');  // 删除自定义预设，返回 boolean
```

### 「全局」目前做到哪一步

这里的「全局」是**工具层面的全局**，只做三件事：

1. 预设持久化到 localStorage；
2. 每次打开空间音频自动套用；
3. 暴露 `window.LIZI_SPATIAL` API 供播放器侧调用。

它**不会**在关闭工具后继续处理主播放器的声音。原因：本工具有自己的 `AudioContext`（解码 buffer + PannerNode），主播放器走 `public/audio/eq-engine.js` 的音频图。要让空间效果作用在主播放器上，需要把 panner 插进 eq-engine 的链路；那会和 EQ 现有的 `MediaElementSource` 抢节点，属于另一轮改造，本轮没有动 eq-engine / player 的音频链路。

## 角度 / 坐标约定

俯视，正前 = 0°，**角度向左增大**（与需求里的「左 90° / 右 270°」一致）：

| 角度 | 方位 |
| --- | --- |
| 0° | 前 |
| 45° | 左前 |
| 90° | 左 |
| 135° | 左后 |
| 180° | 后 |
| 225° | 右后 |
| 270° | 右 |
| 315° | 右前 |

世界坐标（Web Audio：X 右、Y 上、Z 前方为 -Z）：

```
x = -sin(θ) * cos(仰角) * d
y = sin(仰角) * d
z = -cos(θ) * cos(仰角) * d
```

`d` 是音响到听者的**真实距离**（0.9–3.4 m），`y` 就是高度（0–3.0 m）。

反算（XYZ 输入框走这一套）：

```
d      = clamp(hypot(x, y, z), 0.9, 3.4)
θ      = atan2(-x, -z)
仰角   = asin(clamp(y / d, -1, 1))
```

- **极坐标是真源**：`speakers` 里只存 `angle / distance / elevation / vol`；XYZ 输入框是派生视图，改 X/Y/Z 后立刻反算回极坐标。
- 高度和仰角是同一件事：`高度 = sin(仰角) × 距离`。拖高度滑杆、按 PageUp/PageDown、输入 Y 都改仰角；拖音响改变距离后，高度读数跟着刷新。
- 高度限制在 **0–3.0 m**（不允许负值，避免箱子穿地）；因为 `sin(仰角) ≤ 1`，实际可达高度不会超过当前距离。

## 音频链路

```
独立 AudioContext（不复用主 <audio>，也不进 beat.js 的图）
  AudioBufferSourceNode（当前歌曲解码后的 buffer，不循环）
    ├─ PannerNode × N   HRTF / inverse
    │    └─ GainNode × N  单个音量 × 1/√N
    └─ 全部汇到 masterGain → AnalyserNode → destination
```

PannerNode：

- `panningModel = 'HRTF'`
- `distanceModel = 'inverse'`
- `refDistance = 1`
- `rolloffFactor = 0.8`
- `maxDistance = 20`
- 全向：`coneInnerAngle = coneOuterAngle = 360`
- 位置用 `positionX/Y/Z.setTargetAtTime(..., 0.035)` 平滑；Y 跟随高度，拖动 / 拉滑杆不会爆音。

增益补偿：每个音响 `gain = 单音响音量 / √N`（N = 音响数），总音量走 masterGain。加音响时总响度大致不变，不会越加越吵。

切换预设时重建音响：旧的 Panner 用 80 ms 增益淡出后再断开（复用 `removeSpeakerAudio`），新音响从 0 平滑推上来，不会「啪」一声。

## 桌面壳（窗口三键 / 拖窗带）

- 窗口三键（最小化 / 最大化 / 关闭）固定在右上角，宽 138px、`z-index: 900`；`.spz` 仍是 280，不跟它抢层。
- `body.is-desktop` 下工具头部 `.spz__head` 右侧留 **162px**（138 + 24 间隙），帮助卡 `#spz-help` 同步左移；浏览器版不受影响。
- 工具打开时给 `body` 加 `is-spatial-open`，隐藏顶部 14px 的 `.drag-strip`（`z-index: 890`），避免拖窗带盖住工具头部按钮；关闭时移除。

## 文件 / 入口

- `public/tools/spatial/spatial.js`：工具本体，挂 `window.LIZI_SPATIAL.open()` / `close()` 和预设 API，CSS 由它自己注入。
- `public/tools/spatial/spatial.css`：浮层样式（铺满窗口，右侧控制台独立滚动）。
- `public/tools/spatial/kitten3d.js`：3D 听者（100k 面小猫）的离屏渲染模块，`spatial.js` 动态 import。相机与 `project()` 严格对齐，只负责把猫画进 2D 舞台。
- `public/tools/spatial/kitten-100k.glb`：小猫模型，100,000 三角面 / 70,907 顶点 / 1024×1024 JPEG 贴图，约 2.7 MB。
- 入口：`public/app.js` 的 `TOOLBOX` 里一行 `id: 'spatial'`。
- 页面：`public/index.html` 里一行 `<script src="tools/spatial/spatial.js" defer></script>`。

### 3D 听者（小猫）的约定

- **离屏合成**：猫渲染在一张不进 DOM 的 WebGL canvas（透明底）上，`drawScene` 的深度排序轮到听者时再 `drawImage` 进 2D 舞台，所以近处音响盖住猫、远处音响被猫盖住，层次和原 2D 小人一致。
- **贴图 flipY**：GLB 里的 UV 是左上角原点（glTF 规范）；trimesh 的 loader 会在读入时把 v 翻成 1-v，而 `kitten3d.js` 直接读原始 GLB，所以用 `texture.flipY = false`。设成 `true` 会再翻一次，贴图上下颠倒、猫会花。
- **朝向**：模型原生面朝 +Z，绕 Y 轴旋转 π 后面朝 -Z，和 Web Audio listener 的 `forwardZ = -1`、原 2D 小人鼻尖一致。默认相机在 +Z，所以默认看到猫背面；拖动空白处转视角可以看到正脸。
- **材质**：模型没有 NORMAL，只有 POSITION / TEXCOORD_0 / indices，所以用 unlit 的 `MeshBasicMaterial`（`MeshStandardMaterial` 会全黑）。
- **兜底**：模型加载失败（404 / 无 WebGL / 解析或贴图失败）只 `console.warn` 一次，继续显示原来的 2D 小人。

## 边界（第一版没做）

- 不做音源文件拖入 / 多轨 / 房间混响 / 自动旋转。
- 当前歌曲整首解码进内存，长歌会占几十 MB；播放器里没有歌、跨域链接、链接失效或解码失败都会明确报错，不会假装成功，也没有测试音可退。
- 实时布局本身不持久化；要跨会话保留就「保存当前」或设为全局预设。
- 全局预设不会把空间效果接进主播放器（见上面「全局」一节）；关闭工具后主播放器仍是普通立体声。
- 高度只允许 0–3.0 m，不支持负高度（避免箱子穿地）。
- 关键帧 v1 是独立时间轴，不跟音源同步；没有缓动曲线、每帧单独编辑、导入导出。
- 关键帧按音响数组下标对应，音响数量变化后不会自动重映射；两帧数量不一致时只处理较小的那一批。
- 坐标轴几乎正对相机时投影退化，会直接不画；轴拖拽到距离 / 高度边界时会被 `setFromXyz` 钳住。
- `prefers-reduced-motion` 只关动画，不影响音频。
